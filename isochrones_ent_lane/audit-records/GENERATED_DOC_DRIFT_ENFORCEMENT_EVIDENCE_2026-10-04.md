## Verdict

ENFORCED. Generated-document drift is detected by regeneration and a
HEAD-relative tracked-tree comparison inside the required `fast gates`
context. A deliberately stale generated artifact was observed reaching that
comparison, failing it, and making the required context red; restoring
canonical generated output was observed passing the same step and making the
same context green, with the enforcement implementation byte-identical between
the two observations. The hermetic state machine reproduces the verdict
sequence in two independent scratch repositories.

## 2026-10-09 re-qualification (fast-gates.yml package-list change)

`ff5dcdb9794e445ddc59f42ecc3c90801b44174b` added `dplyr`, `tibble`,
`lubridate`, `DBI` to the `fast-gates` job's shared package list (for an
unrelated step, the retirement-boundary merge-regression sentinel). DE-09's
`workflow_step_projection` comparison treats the whole job's package list as
part of what every step in that job executes, so this changed `p_now` for
every verdict qualifying any step in `fast-gates`, including this one. DE-09
correctly failed on the next PR, naming exactly that: `[1] "DBI" [4]
"dplyr" [7] "lubridate" [10] "tibble"` present now, absent at the old
`qualifies_head`.

**What did NOT happen this time, and why.** The 2026-10-04 methodology
(push a probe commit to `main`, watch the required `fast gates` context go
red on a real run, revert, watch it go green) could not be repeated.
`DE-08` -- a permanent regression guard added after that original
experiment, specifically asserting the probe marker is absent from any
branch -- runs in the SAME `tests/preflight_contract` step as DE-09, ahead
of the actual `Generated documentation surfaces cannot drift` step in the
job. A pushed probe trips DE-08 first, and the job stops there: the target
step is skipped, not failed, so it produces no fail-before evidence and
leaves the required context red on `main` for no reason connected to the
thing being re-qualified. This was discovered live (commit `f4e228808`
pushed to `main`, observed failing on DE-08 as well as DE-09, with the
drift step skipped; `43154ec54` then fixed `qualifies_head` alone and
confirmed DE-09 cleared while DE-08 still blocked the target step) and
reverted (`87e880770`) rather than left on `main`.

**What happened instead: a hermetic reproduction, same standing as DE-05.**
Two commits were made on a local-only branch (`de09-local-reproduction`),
never pushed to any remote, branched from `87e880770`:

| commit | content | local comparison (`git diff --exit-code HEAD --` after running every generator) |
|---|---|---|
| `0ea7c077b63ec409a6ae3d8a3d4193fd8a1621ae` | hand-edited `docs/pipeline/GENERATED_STEP_REGISTRY.md` row 78 with the `DELIBERATELY STALE` marker (identical edit to the 2026-10-04 probe) | exit 1; diff named exactly the one mutated row |

Both generator runs and both comparisons were executed directly (the same
shell commands `fast-gates.yml`'s step body runs), not simulated or
inferred. `tests/preflight_contract/test-generated-doc-drift-enforced.R`
was also run locally at the pass-after commit: 163 passed, 0 failed, 0

skipped on a missing qualifying commit.

This is a weaker claim than the 2026-10-04 live-CI evidence in one specific
sense: it does not observe GitHub Actions itself (runner environment,
required-context plumbing, branch protection) executing the comparison,
only the identical logic executed locally. It is not weaker in any way
connected to what actually changed (the package list) -- that comparison
is unaffected by runner-vs-local execution. DE-05 already established this
repository's standing precedent that a hermetic local reproduction is valid
evidence for this mechanism; this is the same standing, applied because
DE-08 makes the live-CI variant structurally unrepeatable now that it
exists.

`qualifies_head` is `87e8807706759e48bccc2be7915050b696da398d`, the real,
pushed `main` commit whose `fast-gates.yml` state (package list included)
this verdict now certifies -- not either local-only commit.
